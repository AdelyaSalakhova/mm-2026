# Московский марафон 2026

Локальный дашборд на Vue.js и D3.js по макету Московского марафона. Данные берутся из `results.json`; в интерфейсе указан 2026 год из источника. Таблица сохраняет порядок исходных данных и показывает по 100 участников на странице. Всего 171 страница; на последней — 38 участников.

## Дашборд

- Общая статистика, возрастная пирамида по одному году и топ-5 стран рассчитаны по всем 17 038 участникам. При наведении на полоску пирамиды видны возраст, пол и число людей. Страны переведены на русский; неизвестная страна показана отдельно. Проценты считаются от всех участников, ненулевые доли меньше 1% обозначены `<1%`.
- Топ-3 мужчин и топ-3 женщин отсортированы по числовому времени финиша среди обоих классов. Это рейтинг по времени из JSON, а не официальный список призёров. Имена ведут на исходные результаты.
- Распределение финишей содержит 16 157 SVG-отметок: один бегун — одна горизонтальная чёрточка. Время сгруппировано в интервалы по 60 секунд. Внутри минуты снизу вверх идут женщины, затем мужчины; внутри каждого пола возраст растёт снизу вверх. При равном возрасте порядок определяется временем, затем номером. Синий означает мужчин, розовый — женщин; светлота увеличивается с возрастом по общей шкале 18–82 года.
- При наведении на отметку показываются имя, возраст, пол, точное время `чч:мм:сс`, страна, класс, исходное место в классе и стартовый номер. Подсказку можно закрыть Escape. На сенсорном экране её вызывает касание отметки.
- 487 DNF и 394 DQ перечислены отдельно и исключены из графика времени и рейтинга. Пагинация изменяет только таблицу. На узком экране блоки перестраиваются, график и таблица прокручиваются горизонтально.

## Запуск

```powershell
npm.cmd install
npm.cmd run dev
```

Адрес для разработки: http://127.0.0.1:5173. Изменения HTML, CSS и JS отображаются сразу.

## Сборка и её проверка

```powershell
npm.cmd run build
npm.cmd run preview
```

Сборка сохраняется в `dist/`, адрес просмотра: http://127.0.0.1:4173. Остановить сервер можно через Ctrl+C. Если данные изменились, повторите сборку перед запуском preview.

## Файлы проекта

- `index.html` — структура дашборда, подсказок и таблицы.
- `styles.css` — оформление и адаптация под узкие экраны.
- `app.js` — приложение Vue, загрузка данных, подсказки и пагинация.
- `dashboard-data.js` — подсчёт статистики, разбор времени и сортировка бегунов внутри минуты.
- `charts.js` — графики D3, SVG-отметки, шкалы, оси и обработка наведения.
- `results.json` — все участники с классами `elite` и `amateur`.
- `vite.config.js` — настройки локального сервера и сборки.
- `convert-results.cjs` — повторная конвертация исходных HTML в JSON: `node convert-results.cjs`.

Ссылки на результаты открываются по имени участника. Значения DNF и прочие статусы сохранены из источника. Места относятся к исходным классам, поэтому повторяются между элитой и любителями. Библиотеки и данные включаются в локальную сборку; для отображения таблицы интернет не нужен.

## Правила для дальнейшей визуализации

Заметки по четырём лекциям курса. Это проектные рекомендации; они не являются дополнительным заданием преподавателя. Страницы указаны по порядку страниц PDF. Правила из лекций и их применение к данным марафона разделены ниже.

### Что берём из лекций

- Неделя 1, стр. 14–19: визуализация должна облегчать восприятие и выявлять закономерности в данных. Перед добавлением графика определяем вопрос, на который он отвечает. D3.js прямо показан среди инструментов на стр. 29.
- Неделя 2, стр. 4–9: показываем данные, сокращаем графический шум; таблица подходит для чтения точных значений и сравнения нескольких параметров. Порядок строк создаёт ранжирование, поэтому смысл сортировки должен быть понятен.
- Неделя 2, стр. 12–14 и 28–29: сравнение категорий показываем столбиками; длина столбика пропорциональна значению, начало шкалы — ноль. Для сравнения долей предпочитаем столбики круговой диаграмме.
- Неделя 2, стр. 15–17; неделя 4, стр. 6: линия требует осмысленной связи и порядка точек. Не соединяем линией независимые категории.
- Неделя 2, стр. 18–23: тепловая карта показывает числовое значение на пересечении двух категорий; диаграмма рассеяния — связь двух количественных параметров. Нужны читаемые оси и легенда для цвета или размера.
- Неделя 3, стр. 9, 15–21: совмещаем параметры для анализа, сохраняем последовательность визуального кодирования и честно показываем структуру данных. Одинаковые категории обозначаем одинаково. Палитры, пропорции и шрифты создают эстетику без отдельных декоративных элементов. На стр. 8 есть пример визуализации Московского марафона.
- Неделя 4, стр. 4–11: не обрезаем нулевую базу столбиков, не складываем несопоставимые величины, не искажаем пропорции. Цветовая шкала должна соответствовать смыслу данных; оттенки одного цвета не должны создавать ложный порядок между независимыми категориями.
- Неделя 4, стр. 12–16: связанные элементы группируем близко; текст выравниваем влево, числовые значения вправо. Указываем единицы, выбираем осмысленную точность, убираем ненужные линии, тени, обводки и 3D-эффекты.

### Применение к данным марафона

1. `finishTime` и `pace` для расчётов переводим в секунды, исходные строки сохраняем для отображения. Длительность не равна времени суток, стартовый номер — идентификатор, а не количественный показатель.
2. `DNF` и `DQ` учитываем как отдельные статусы, не как нулевое время. В текущем JSON: 17 038 записей, 16 157 с числовым временем, 487 DNF и 394 DQ. Для статистики действительных результатов исключаем оба статуса и явно показываем размер выборки. Запись с DQ может относиться к человеку, пересёкшему финиш, поэтому нельзя автоматически называть его не финишировавшим.
3. `place` — место внутри исходного класса. Нельзя выдавать его за общий рейтинг после объединения файлов. Класс обозначаем явно, исходное место сохраняем; другой рейтинг требует отдельного определения.
4. Все сводные графики считаем по полной выборке после фильтрации, а не по 100 строкам текущей страницы. Пагинация влияет только на таблицу.
5. При сравнении классов показываем размеры групп: 32 elite и 17 006 amateur. Количество и доля отвечают на разные вопросы; для процентов указываем знаменатель. Выводы по небольшим группам формулируем с учётом их размера.
6. Распределение результатов реализовано по минутам с отдельной отметкой для каждого бегуна. Для связи возраста и времени в будущем подходит диаграмма рассеяния; для количества по странам можно добавить столбики.
7. Один цветовой словарь используем во всех графиках, таблице и легендах. Категориальные цвета различают группы; последовательная светлота передаёт величину, расходящаяся палитра требует осмысленной центральной точки.
8. Возрастные группы определяем явно и без перекрытия границ. Страну берём из поля `country`; не интерпретируем её как место проживания без дополнительных данных.
9. Заголовки графиков называются по аналитическому вопросу, оси содержат единицы: возраст в годах, результат в часах/минутах, темп в мин/км. Числовой темп в агрегатах не считаем независимым от времени на одной фиксированной дистанции.

### Учтённые уточнения интерфейса

- Колонка переименована в «Место в классе».
- Время показывается в формате `чч:мм:сс`, возраст — в годах; пояснения DNF и DQ доступны при наведении на подпись статусов.
- Числовые значения места, возраста и темпа выровнены вправо; номер остаётся идентификатором.
- Декоративный блок заменён аналитикой на белом фоне без рамок вокруг секций.
